# New store recipe

How a new store is assembled from the `@ecomkit/*` modules. `apps/minimal` is the working proof: core, ui, auth, media, catalog, pricing, inventory, cart, checkout, payments, orders, customers and seo, no Hasiru-only modules. It typechecks, builds, and `/`, `/plants`, `/plant/<slug>`, `/cart`, `/checkout` return 200 from `next start`.

## 1. Create the app

1. Copy `apps/minimal` to `apps/<store>`; rename `name` in `package.json` and pick a free port in the `dev`/`start` scripts (shop 3000, minimal 3100).
2. Add the app to the workspace (it is already covered by `apps/*`), then ask the orchestrator for `pnpm install` (agents never install).
3. Keep per-app files as they are: `next.config.ts`, `postcss.config.mjs`, `drizzle.config.ts`, `instrumentation.ts`, `image-loader.ts`, `app/layout.tsx`, `app/globals.css`, `theme.css`.

## 2. Pick modules

Edit one list, `apps/<store>/modules.config.ts`:

```ts
export const modules: readonly ModuleId[] = ['core', 'ui', 'auth', 'media', 'catalog', 'pricing', 'inventory',
  'cart', 'checkout', 'payments', 'orders', 'customers', 'seo'];
```

Rules: a module's `dependsOn` (in its `manifest.ts`) must be in the list; `optional` ones may be left out and the host page renders nothing for that part. Then run:

```
pnpm modules:sync --app <store> --config dev     # writes routes, src/generated/registry.ts, src/generated/schema.ts
pnpm modules:sync --app <store> --check          # CI: fails when generated files are stale
```

The sync generates every route file and the registry; never edit `src/generated/*` or files headed "generated by modules:sync". Only enabled modules get routes, schema tables, jobs, sitemap sources and admin pages, so a store without `reviews` has no review tables.

The shell is yours: `app/(shop)/layout.tsx` (header, footer), `app/(shop)/page.tsx` (home) and shell copy (`messages.ts`). Modules supply the rest.

## 3. Theme with tokens

Modules style themselves only with semantic tokens from `@ecomkit/ui/tokens.css` (`--color-bg`, `--color-primary`, `--radius-md`, `--font-body`, ...). Override them in `apps/<store>/theme.css` under `:root, [data-surface='shop']` and import it from `app/globals.css` after the ui tokens. Fonts: set `--font-display` / `--font-body`, loading them with `next/font` in `app/layout.tsx`. No colour literals anywhere else. `minimal/theme.css` (slate and indigo) vs `shop/theme.css` (green and cream) show the same modules in two looks.

## 4. Database and seed

```
pnpm db:fresh <store>                                  # throwaway ecomkit_<store>, prints DATABASE_URL
DATABASE_URL=... pnpm -F <store> exec drizzle-kit push # dev only; production uses reviewed migrations
psql "$DATABASE_URL" -f apps/<store>/seed/seed.sql     # idempotent starter data
```

`apps/minimal/seed/seed.sql` seeds one collection and 5 generic products, each with one default variant, a price (`pricing_price`) and stock (`inventory_level`). A real store uses the catalog import (`/admin/import`) or the module `seedHooks` via `pnpm seed:load --app <store>`.

## 5. Environment

`DATABASE_URL`, `SITE_URL`, `NEXT_PUBLIC_SITE_URL`, `INTERNAL_SECRET` (32+ chars), `INTERNAL_BASE_URL`, `SETTINGS_MASTER_KEY='1:<base64 32 bytes>'`, `MEDIA_ROOT` (absolute), `ENABLE_MOCKS`. In a production build (`next start`) `ENABLE_MOCKS` must be `0`; the payments mock gateway works under `next dev` or a non-production `NODE_ENV` only. Payment credentials are entered in admin settings, not env.

## 6. Build and verify

```
pnpm turbo run typecheck lint test --filter=<store>
DATABASE_URL=... SITE_URL=... INTERNAL_SECRET=... SETTINGS_MASTER_KEY=... ENABLE_MOCKS=0 pnpm -F <store> exec next build
pnpm -F <store> exec next start --port <port>        # curl /, /plants, /plant/<slug>, /cart, /checkout expecting 200
pnpm turbo boundaries
```

`next build` needs `DATABASE_URL` (static params query the catalog).

## 7. Adding Hasiru-only modules later

Add the id to `modules` and re-run `modules:sync`; nothing else changes. The ids that are specific to the Hasiru store: `planting`, `planting-3d`, `farm-calculators`, `truck-meter`, `hasiru-ops-adapter`, `erp-sync`, `places` (district delivery), `ai-assistant`. Generic extras a new store may also want: `search`, `cms`, `discounts`, `enquiries`, `reviews`, `notifications`, `analytics`, `monitoring`, `feeds`, `shipping`, `marketing`, `flows`, `admin-shell`. Each module's README lists its dependencies and env. Add the module's own package to the app `package.json` dependencies (`workspace:*`) and ask for an install.

Known leftovers in the proof app (catalog route names are plant-flavoured): products live at `/plant/<slug>` and listings at `/plants`; rename by editing the catalog route table in `packages/catalog/src/manifest.ts` (affects every store), and the minimal app has no `admin-shell`, so `/admin/*` pages use the small layout in `app/(admin)/layout.tsx`.
