# @ecomkit/inventory

Stock per variant, reservations with a TTL tied to the payment attempt, an append-only movements ledger, availability derivation, low-stock events, the ERP override rule (manual counts win until cleared) and back-in-stock ("notify me") subscriptions. Brand-neutral; any store can enable or drop it.

Hard dependencies: `core`, `catalog`. Provides the `inventory` service (`InventoryOps` from `@ecomkit/core/contracts`).

### Rules the code enforces

- **Sellable** = `on_hand - reserved`, floored at 0. Sellable > 0 is `in_stock`; 0 with `ready_in_days` is `preorder`; else `out_of_stock`. `lowStock` when sellable is between 1 and the threshold (variant threshold, else the `defaultLowStockThreshold` setting).
- **Reserve** locks the level rows in `variant_id` order (`SELECT ... FOR UPDATE`) and holds all lines or none; a shortage returns `{ ok: false, shortages }` and writes nothing. Pass `tx` to hold stock inside the caller's order transaction. Concurrent reservations never oversell (tested with 25 parallel transactions).
- **Commit** moves the held qty out of `on_hand` (ledger reason `order`, ref = reservation reference). Idempotent; on a released reservation it throws `ReservationError('released')` so orders can raise the late-payment alert (A27).
- **Release** and the **TTL sweep** return holds to sellable stock. The sweep job runs every minute and uses `SKIP LOCKED`.
- **Ledger**: every change to `on_hand` writes one `inventory_movement` row; `sum(delta) = on_hand` per variant (tested).
- **A26**: `setLevel` and `adjust(reason 'adjust')` mark the row `manual`. `setFromErp` never changes a manual row's count; it records the ERP number in `erp_on_hand` (drift) and skips items older than the last one applied. `clearOverride` hands the row back to the ERP, starting from `erp_on_hand`.
- **Events** (transactional outbox, only when sellable stock changes): `stock.changed`; `stock.low` once when sellable crosses the threshold from above.

## Tables

`inventory_level` (pk `variant_id`, `product_id` denormalised, `sku` snapshot, `on_hand`, `reserved`, `ready_in_days`, `low_stock_threshold`, `source` manual|erp|seed, `erp_on_hand`, `erp_updated_at`), `inventory_reservation` (pk `(id, variant_id)`: one id per reserve call, one row per variant; `reference`, `expires_at`, `status` held|committed|released), `inventory_movement` (ledger), `inventory_subscription` (unique per variant + phone + email; `consent_id` nullable until customers exposes consent).

## Routes

| Path | What |
|---|---|
| `POST /api/notify-me` | `{ variantId, phone?, email?, consent: true }`. 201 created, 400 invalid, 404 unknown variant or feature off, 413 body > 4 KB, 429 over 10 per hour per IP, 202 on a filled honeypot (`website`). |
| `/admin/inventory` | DataTable: search SKU or id; filters `source`, `state` (in_stock, low, preorder, out_of_stock); sort sku, available, updated. Permission `inventory.read`. |
| `/admin/inventory/[variantId]` | Level, forms (count, threshold, ready in days, Clear override) and the movements ledger. Writes need `inventory.write`. |

Route files under `apps/*/app` are generated by `modules:sync` from the manifest.

## Settings (`/admin/settings/inventory`)

`defaultLowStockThreshold` (default 5; 0 turns low-stock off for variants without their own), `notifyMeEnabled` (default true).

## Events, jobs, extension points

- Emits `stock.changed`, `stock.low`. Subscribes to `stock.changed`: expires `stock:<productId>` and `stock:<variantId>`, then sends `stock.back_in_stock` to pending subscribers when sellable > 0.
- Job `inventory.release-expired`, schedule `* * * * *` (Asia/Kolkata).
- `productFormTabs`: Inventory tab (order 30). `pdpSections`: `inventory.notify-me` (slot `aside`; reads live stock, so the PDP renders it inside a Suspense boundary). `seedHooks`: `inventory.levels` (reads `products.json` / `inputs.json` variants `stock_qty`, `ready_in_days`, `low_stock_threshold`; resolves sku to ids through `@ecomkit/catalog/server` `variantRefsBySku`, and skips with a note while that export is missing).
- Admin nav: Inventory in the Products band (order 230).

## Wiring in the host app

- Back-in-stock messages need the notifications service: call `setNotificationsProvider(() => registry.service('notifications'))` once in the web process and the worker (same pattern as `setAuthProvider`). Unbound, subscriptions stay pending and nothing is sent.

## Disable

Remove `inventory` from the app's module list and run `modules:sync`. Modules that read stock through `registry.service('inventory')` get null and should degrade (contract rule); the tab, PDP section and nav item go with the module. The tables can be dropped with the next migration.

## Tests

`pnpm turbo run typecheck lint test --filter=@ecomkit/inventory` (real Postgres, one database per test file: `ecomkit_wp_07_*`). Covers: parallel reservations never oversell (and fail without the row lock), multi-line opposite-order reservations without deadlock, all-or-nothing shortages, caller transaction rollback, commit idempotency and ledger rows, TTL sweep boundaries, the real worker running the scheduled sweep and the `stock.changed` subscriber, ERP pull vs manual rows, stale and negative ERP items, ledger sum after mixed operations, event outbox and low-stock crossing, seed idempotency, notify-me route statuses, honeypot, rate limit, delivery with claim and retry, manifest wiring and codegen paths, admin tab and PDP section rendering.
