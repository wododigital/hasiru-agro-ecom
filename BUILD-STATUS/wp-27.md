## Assumptions (A27-n, 2026-10-20)
- A27-1: Manifest `erp-sync.dependsOn = ['core', 'inventory']`, `optional: ['orders', 'customers', 'catalog']` (plan: core, orders, inventory). `hasiru-ops-adapter.dependsOn = ['core', 'erp-sync']` (plan: erp-sync, customers). Orders is in this wave without a public API yet, and a store can sync stock without orders; all order, lead and catalogue data comes through ports.
- A27-2: The adapter is bound with `configureErpSync({ adapter, orderPayload, leadPayload, onPushed, applyOrderStatus, variantCandidates })` (the Wave 1 `configureX` pattern), not a new `ServiceMap` key (contracts are frozen). Every port is optional and degrades.
- A27-3: Outbox payloads are built at the first push attempt from fresh state (events carry ids) and stored on the row (CSV bridge, audit). The ERP order id is stored on `erp_outbox.external_ref` (+ `invoice_number`) and handed to orders through `onPushed` / `erpRefFor(orderId)`, instead of erp-sync writing `orders_order.erp_order_ref`.
- A27-4: Tables beyond plan section 3: `erp_item` (last-seen ERP catalogue for the unmapped list and the drift report) and `erp_webhook_event` (nonce dedupe). `erp_outbox` gained `external_ref`, `invoice_number`, `created_at`, `updated_at`, unique `(kind, ref_id)`.
- A27-5: Orders are queued on `order.paid` and on `order.confirmed` (cash and pay-at-nursery); one row per order. The "same transaction" rule is met by core's transactional emit: the event job commits with the order, the subscriber writes the row.
- A27-6: Retry: 30 s doubling, capped at 1 h, `maxAttempts` 10 (setting), then `dead`. A missing endpoint (`NotConfiguredError`) or missing port keeps the row `pending` without spending an attempt and retries every 15 min (setting).
- A27-7: Dead-letter alert = `captureError` (one issue) + critical health check `erp-sync.dead-letter` (down while dead rows exist; monitoring alerts on critical checks) + `integration.failed` per failed call from `integrationCall`. No direct monitoring import.
- A27-8: Cron cannot be admin-edited, so the pull job is scheduled every minute and skips itself until `pullEveryMinutes` (default 10) has passed; "Sync stock now" forces it. Every pull is a full pull (`since = null`): needed for the unmapped list and for zeroing, and cheap at a few hundred items.
- A27-9: A linked item the ERP stops reporting is set to zero stock, only after a complete pull without errors.
- A27-10: hasiru-ops `items` has no `sku` column (plan assumed one). `sku = null`; matching uses name and `variety + size_grade`; `cost_rate` rupees become paise.
- A27-11: Both hasiru-ops tables have row level security with staff-only policies, so a SELECT grant alone returns zero rows. The role script adds a read-only policy per table (`create policy ecom_sync_read ... for select to ecom_sync using (true)`); never BYPASSRLS. `location_id` is not read (stock summed across locations); inactive and `track_stock = false` items are skipped.
- A27-12: Every pg read runs on a short-lived connection inside `BEGIN TRANSACTION READ ONLY` + `SET LOCAL statement_timeout = '10s'` and is rolled back (works through transaction poolers where session settings do not stick); the role also defaults to read-only. TLS is required unless the host is loopback; the URL's `sslmode` is honoured.
- A27-13: Signing string = `timestamp \n nonce \n METHOD \n path-with-query \n body` (the plan signed timestamp + method + path + body with a separate nonce; including the nonce stops nonce swapping). Hex HMAC-SHA256, one shared secret both directions, 300 s window.
- A27-14: `transport` selects only the stock source. Orders always go to `ops-api` (or the mock in `mock`), leads always to the intake URL (or the mock). Mock mode on both sides uses `derivedSecret('hasiru-ops-mock')`, never a configured secret.
- A27-15: Lead intake body: `source = ecom-<lead source>`, `lead_type = service` for enquiries else `nursery`, `message` carries purpose, land, district, notes and the store lead id. The endpoint is create-only and returns no id, so a retry after a lost 201 can duplicate (documented in the spec).
- A27-16: The status webhook route lives in hasiru-ops-adapter (it owns the secret); erp-sync stores the nonce and calls `applyOrderStatus`. Unknown order or no port answers 200 with the outcome (the ERP must not retry forever). 120 requests a minute per IP hash, 64 KB cap, identical 401 bodies.
- A27-17: Admin placement: `/admin/erp` in the Health band (`health.read`); mapping as the settings custom panel; Sync now (`inventory.write`), Push now and Retry (`jobs.retry`); pending-orders CSV (`orders.write`, the people who key orders in); dashboard tile (`orders.read`); drift report group `inventory` (`inventory.read`).
- A27-18: Test connection is an action on the hasiru-ops-adapter settings (where the credentials are), not on erp-sync.
- A27-19: Without a catalog port, auto-mapping falls back to inventory SKUs (exact SKU only). Admins link by variant SKU or id through a native datalist.
- A27-20: No hand-written file under `apps/shop/app/api/webhooks/ops/`; `modules:sync` generates it from the manifest route (checked with a local, reverted `modules:sync` + `next build`).
