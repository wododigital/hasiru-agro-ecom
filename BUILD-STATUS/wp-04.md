## Assumptions (numbered, dated)
- A04-1 (2026-10-20): Cross-module capabilities without a `ServiceMap` key (media `ImageRef`s, media ids for seed masters, seo `jsonLd` / metadata / `addRedirect`, search facet sidebar, host messages) and the registry itself reach the catalog through `configureCatalog(...)`, bound once by the app on `globalThis` (same pattern as core `setAuthProvider`). Unbound capabilities degrade to nothing.
- A04-2 (2026-10-20): Slug change keeps the old slug in `catalog_product.previous_slugs` (new column) and the PDP answers it with Next `permanentRedirect` (HTTP 308, permanent). The 301 proper comes from the seo module's redirect table via `addRedirect(from, to)` after commit; a redirect-writer failure is logged and does not fail the save.
- A04-3 (2026-10-20): `/plants/[collection]` serves both top-level plant collections and curated pages: a `catalog_tag` with `kind = 'trait'` and at least one visible product is a curated page (`/plants/drought-tolerant`, `/plants/nitrogen-fixing`, `/plants/native-saplings`). Seed import derives the first two from `drought_tolerance = high` and `nitrogen_fixer`; native saplings need a `native-saplings` tag in the seed (request to WP-14). Non-trait tags and empty curated pages 404.
- A04-4 (2026-10-20): Without `data/seed/collections.json` collections derive from product codes (`fruiting`, child `desi`), so URLs read `/plants/fruiting/desi`; the plan's `/plants/fruiting-trees` naming needs WP-14 to ship `collections.json` (`code, slug, name, kind, parent, position, intro_html, seo_*`). "&" in a subcategory is a separator: "Native & medicinal" -> `native-medicinal`.
- A04-5 (2026-10-20): Added columns beyond the plan: `catalog_product.previous_slugs text[]`, `catalog_product.attributes jsonb` (fruit size/shape, intercropping, bearing and rotation display text), `catalog_faq.key` (seed natural key, unique), `catalog_faq.created_at/updated_at`, `catalog_collection.created_at/updated_at`, `catalog_tag.intro_html` (curated page intro), `catalog_variant.sku_suffix` (natural key within a product). `timber_rotation_years` stores the lower bound; the range text stays in `attributes`.
- A04-6 (2026-10-20): Seed FAQ status mapping: approved -> `published`, needs_client -> `client_only`, draft -> `ai_draft` when the source is ai_draft else `answered`. Only `published` FAQs with an answer render and feed FAQPage. Product-embedded FAQs get key `<sku>:faq-<n>`.
- A04-7 (2026-10-20): Seed import is authoritative for product, variant, collection and FAQ fields on every run (it overwrites admin edits to seeded fields); tag names and kinds are admin-owned after the first load. Seed prices and stock are not imported here (pricing and inventory seed hooks own them).
- A04-8 (2026-10-20): The grower-sheet import matches by variety + base name (or name or a search alias), updates agronomy columns only and never base name or variety (the match key); unmatched rows become drafts (`needs_review`, sku = slug upper-cased). Categories in the sheet are not re-applied to existing products (collections are admin-managed); export writes subcategory + up to two `use` tags into the category columns.
- A04-9 (2026-10-20): Listing in-stock filtering and facet filtering belong to the search module (client side over `/facets.json`); the server listing orders purchasable products first and serves `sort` and `page` for crawlers. `?page=n` alone keeps a self canonical and stays indexable; any other query is `noindex,follow` with the clean canonical.
- A04-10 (2026-10-20): Buttons speak an HTTP contract to the cart module: `POST /api/cart/lines` JSON `{ variantId, delta }` -> `{ qty }`, and a plain form post (`variantId`, `qty`, `intent=add|buy`) answering 303 to /cart or /checkout; a `cart:changed` window event follows. Buy buttons render only when `registry.has('cart')`. Notify me posts `variantId, phone, email, consent` to `/api/notify-me`.
- A04-11 (2026-10-20): The PDP land mini-calculator, delivery check, "Grows well with" from model roles, dosage calculator and reviews list come from their modules through `pdpSections`; the catalog renders the slots plus its own companions rail from `catalog_related`.
- A04-12 (2026-10-20): Cache Components: the PDP shell awaits only cached work (catalog reads, and `pdpCommerce` / `cachedImages` / `cachedSettings` wrappers tagged `price:<productId>`, `stock:<productId>`, `reviews:<productId>`, `settings:catalog`); district fit, companion cards and listing results stream in Suspense. Pricing, inventory and reviews must expire those product-id tags on change (requests below).
- A04-13 (2026-10-20): `generateStaticParams` returns a `_none` placeholder (404) when the catalogue is empty, because Cache Components needs at least one entry; builds need `DATABASE_URL` at build time.
- A04-14 (2026-10-20): Card CTA ids repeat per card (`card-add-to-cart`, `card-notify-me`, `card-open-product`); CONVENTIONS "unique per page" is read as one id per CTA kind.
- A04-15 (2026-10-20): Card and PDP render `name_kn` with `lang="kn"` (the column is the Kannada name per the plan schema); admin labels it "Local-language name" and the gap id is `no_local_name`.
- A04-16 (2026-10-20): `@ecomkit/media` stays a declared hard dependency (manifest `dependsOn`) but is not imported yet: its API is being written in parallel (WP-03), so images arrive through the runtime binding.
