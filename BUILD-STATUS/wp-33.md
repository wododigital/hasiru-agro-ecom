## Assumptions
- A33-1 (2026-10-20): KPI cards are dashboard widgets whose id contains `.kpi.` (Home strip, Analytics overview); widgets receive `compare` next to the contract's `range` as an extra prop (the frozen `DashboardWidget` type names only `range`, so a widget declares `compare?` itself). Supersedes A29-4.
- A33-2: "Things to do" is a structural manifest key `adminTodos` (read and zod-validated by admin-shell like `adminSearch` / `settingsUrls`). Each count reuses the module's own list query with `pageSize: 1`, so it equals the list it opens and carries that list's permission check.
- A33-3: Revenue (sales, AOV, top products, returning customers) needs `analytics.read`; operational counts keep their module permission. Support therefore sees no revenue cards.
- A33-4: Sessions and conversion rate come from first-party analytics (browser-tracked purchases over sessions); sales, orders and AOV from `orders_order`. Shopify does the same split.
- A33-5: Report and Live view pages live in `@ecomkit/analytics`; hosts pass `registry.list('reports')` / KPI widgets through hand-written app files (same pattern as the existing analytics host file). Without them the package routes show only analytics' own.
- A33-6: Discounts filter and page in memory (rules are few; `listRules` has no paging).
- A33-7: `stopped_by_staff` added to flows `STOP_REASONS` (text column, no migration). The never-written "link opened" label on abandoned checkouts is dropped (resolves F2-1 the simple way).
