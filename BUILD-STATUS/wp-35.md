# WP-35 Checkout contact reaches the cart for abandoned-cart reminders (status: done, one blocker found outside scope)   updated 2026-10-20

Worktree `.worktrees/wp-35`, branch `wp/wp-35` from ecom-build c14131c. Committed, not merged, not pushed. No dependencies added, no contract change, no migration. DB `ecomkit_wp35`, port 3351.

## Root cause
Checkout's `saveContact` stored the phone/email on `checkout_session` and emitted `checkout.contact_saved`, but nothing called cart `noteContact(cartId)`. `cart_cart.contact_at` therefore stayed null, and `cart.abandoned` carried `hasContact: false` for every guest who typed a contact and left (FINAL-REPORT item 7, BUILD-STATUS open item "cart noteContact is never called").

Traced path:
- **Island:** `CheckoutFormIsland` autosaves on blur of name/phone/email, debounced 400 ms, through `saveContactAction`. There is no server-side rate limit; writes only touch the caller's own cookie cart.
- **saveContact:** writes the `checkout_session.contact` row, then emits `checkout.contact_saved` only when the phone or email changed.
- **cart.mark-abandoned:** runs every 5 min. It picks active carts with lines that have been idle for `abandonAfterMinutes`, and `hasContact` = `customer_id` or `contact_at`.
- **flows:** `onCartAbandoned` starts `abandoned_cart` for every abandoned cart. The boot snapshot reads the checkout-session contact by cart id, the flow needs marketing consent (`needsConsent: true`), and a run with no consent is recorded as stopped `no_consent`.
- **Reminder:** carries `restoreLink` → `/api/cart/restore`.

So the reminder itself already worked for a guest with consent (the boot agent made the flows snapshot read the session contact). What was broken was the cart's own record of the contact (`contact_at` / `hasContact`). A signed-in buyer's account contact was also only stored if they blurred a field.

## Fix
- `packages/checkout/src/server/ports.ts`: the cart port gains `noteContact(cartId, { tx })`.
- `packages/checkout/src/server/checkout.ts` `saveContact`: calls `cart.noteContact` in the same transaction as `checkout.contact_saved`, only when a phone or email is saved.
- `apps/shop/src/boot.ts`: binds the cart module's `noteContact`.
- `packages/checkout/src/ui/CheckoutFormIsland.tsx`: a signed-in buyer's prefilled account contact is saved once on mount. It is a POST, not a GET-time write, and a server no-op when the session already has it. Consent is never written here.
- Cart page: has no contact field, so nothing to cover. Signed-in carts already count as `hasContact` through `customer_id`.
- `packages/checkout/README.md` updated.

The new `--only=jobs` abandoned-cart steps (they replace the old raw-SQL contact write):
1. Two guests each add to cart, open /checkout and save only a phone through the real `saveContactAction` (action id read from the build's `server-reference-manifest.json`). One also ticks consent through `marketingConsentAction`.
2. Assert `contact_at` is set on both carts.
3. Age both carts, enqueue `cart.mark-abandoned` once (the `*/5` cron misses its minute on a loaded host), and assert both are abandoned with `hasContact` true.
4. Phone only, no consent: the run is stopped `no_consent` with 0 messages.
5. Phone + consent: the run starts, `cart.reminder_1` is queued, and the restore link works (GET 200, POST 303 → /cart).
6. The restored cart places an order: the cart is converted, the run is stopped `purchased`, and no later reminder is sent even when made due.

## Blocker found (outside scope, reported to the lead, not changed)
In a production build, the nonce CSP from `apps/shop/proxy.ts` (`NONCE_PREFIXES` /admin, /account, /checkout, /pay: `'self' 'nonce-X' 'strict-dynamic'`) blocks every Next script on those pages. They are partial prerenders (`x-nextjs-prerender: 1`), and the static shell's script tags carry no nonce. Playwright counts: /checkout 18 blocked, /admin/login 16, /account 17; / and /cart 0. The pages never hydrate, so:
- checkout autosave, consent tick, re-quote and pincode autofill never run in a browser;
- customer OTP sign-in and admin client islands are dead too.

No-JS form paths still work, which is why smoke (no JS) stays green. Until this is fixed, a real shopper's contact is only captured at order placement. Options:
1. Use the storefront's static CSP on those prefixes too.
2. Make those segments fully dynamic so Next can nonce every script.

## Open
- CSP blocker above (A25 owner / lead decision).
- A signed-in customer who abandons on the cart page and never opens checkout gets no reminder: the flows snapshot has only their `customerId`, and their phone/email live on `auth_user`, which the worker cannot reach (auth server code is not bound in the worker). This needs a contact-by-customer port: `customers_profile` is only created on profile edit, not at sign-up.
- `saveContact` rejects the whole autosave when the phone is partially typed/invalid, even if the email is valid (the island ignores the error; the next blur retries).
- Contract: `hasContact` on `EventPayloads['cart.abandoned']` is still the WP-17 open request; flows does not read it.
- Worker: after DB connect timeouts the pg-boss `*/5` schedules stopped firing until a restart (every-minute ones kept running). Seen only under extreme host load.
