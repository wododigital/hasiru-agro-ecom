# WP-34 home product rails, calculators, listing filters (status: done)   updated 2026-10-21T08:55+05:30

## Shipped
- **cms block types** (`packages/cms/src/domain/blocks.ts`, `src/ui/blocks.tsx`, `src/server/runtime.ts`):
  - `product_rail` takes eyebrow, heading, source (`bestsellers | collection | tag | ids`) with a slug or product ids, kind (`plant | input`), limit and an optional link. It is validated, so a collection or tag without a slug, ids with no products, or an unsafe link are rejected.
  - `component` embeds a host-registered component by key.
  - Both render through ports the host binds: `configureCms({ productRail, components })`. cms imports neither catalog nor farm-calculators.
  - The heading is in the static shell. Port output renders after `connection()` inside a Suspense hole, because build workers prerender shells before any port is bound.
  - The page editor fills the "Embedded tool" choices from the registered components, so admins can add, edit and reorder these blocks.
- **Trust band** is now a running marquee (ui `Marquee`) of the shown claims with their logos, on dark green with a gold border, as in the prototype.
- **catalog**:
  - `ProductRail` (`src/ui/ProductRail.tsx`) shows the best sellers first, then tops up with in-stock products of the same kind, or a collection, tag or hand-picked ids. It renders in a ui `Rail` of `ProductCard`s with `CardBuyIsland` +/- buttons.
  - The `listingAside` port is replaced by `listingFacets` (`ListingFacetsProps`: every scope product id in display order plus its server-rendered card). When it is bound, `ListingPage` hands the whole scope to it instead of the sort form and numbered pages.
- **Card**:
  - New quick facts line: height at dispatch, sunlight and temperature range (`ProductCardData.facts`).
  - The "New" chip from `Rating` no longer appears on cards with too few reviews, which removes the duplicate "New" pill next to the price.
- **Seed data**:
  - `is_best_seller` now follows the old shop's "featured" flag (the prototype rule). There are 5 such products: before, all 55 client priority plants carried the badge. `is_priority` is unchanged. Updated in `fill-gaps.ts` and in `data/seed/products.json`.
  - Seeded products are dated `SEED_LISTED_AT` (2026-01-01 IST) unless the record has `published_at`, so the opening catalogue no longer shows as "New". On a fresh DB, 0 products are inside the 30-day window.
- **search**: new `cat` (top-level collection) and `sub` (sub-category) facets, with labels taken from the data.
- **App**:
  - `apps/shop/src/route-ui.tsx` adds slots for components with client islands. The storefront layout publishes them and boot binds them.
  - `src/listing-facets.tsx` sets up the search facet UI: desktop sidebar, mobile `FilterSheet`, quick chips, applied chips, sort and "show more". It also adds a "Fits my district" facet from the places service when a `district` cookie is set.
  - The home page (`app/(shop)/page.tsx`) renders the prototype hero, with text and image from the home page's `hero` block, then the cms blocks. It has no cms title or breadcrumb, and one h1.
- **Home seed order** (`tooling/scripts/seed/cms-content.ts`, `data/seed/cms.json`): hero, best sellers rail, plant calculator, inputs rail, compost calculator, trust band, videos, testimonials, farm development, why choose us.
- **Core**: `DATABASE_POOL_MAX` sets connections per process (default 10). It is documented in the env schema, the core README and FINAL-REPORT section 1. Builds use `DATABASE_POOL_MAX=2`.
- **Smoke**: new `storefront` section, in the default set. It checks that the home page lists products with add buttons, that both calculators are embedded, that there is one h1 and no cms title or breadcrumb, that `/plants` has facet checkboxes and a sort control, and that a facet value narrows the results.

## Known failures / flaky tests
- With Postgres at its 100-connection limit (other worktrees), a worker's pg-boss loop stalled. Cron jobs fired only at worker start, and payments and erp jobs went to `.dead`. Restarting the worker cleared it, and money and jobs then passed. This is environmental: wp-34 changes no job code.

## Incomplete / next steps
- **Prerendered shells are built without bound ports (affects the whole store; already true on ecom-build).** `next build` workers never run instrumentation `register()`. Static shells therefore render with default messages, no images and no registry: the main-tree `.next/server/app/index.html` has 5 leaf placeholders and 0 `<img>`. The request-time render, which does have the ports bound, then disagrees with the shell. Result: React hydration error #418 on `/` and `/plants`, and images that appear only after hydration (the "blur placeholders" in the report).
  - Fix: call `boot()` from the root layout and cache media `getImages` under a `media` tag.
  - I tried this: the build then fails on `/[...slug]`, because the media read is uncached outside Suspense. It needs the media cache plus an audit of other uncached port reads, so I left it out of this package.
- Farm inputs have no photos (FINAL-REPORT item 8), so the inputs rail shows leaf placeholders.
