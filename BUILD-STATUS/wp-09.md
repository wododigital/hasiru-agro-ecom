## Assumptions (numbered A09-n, dated 2026-10-20)
- A09-1: Site identity (name, logo, address, geo, hours, phone, return policy, search path) is host config passed to `configureSeo({ site })`, not seo settings: JSON-LD builders are synchronous (core contract) and the plan puts nursery details in General settings, which do not exist yet. WP-28 builds `site` from env `SITE_URL` + messages/General settings at boot and may call `configureSeo` again when settings change.
- A09-2: seo and cms reach the app registry and each other through runtime bindings (`configureSeo`, `configureCms`), the same pattern as catalog's `configureCatalog` and core's `setAuthProvider`, so all routes stay generated stubs and neither module imports the other.
- A09-3: Added `cms_team_member` (not in plan section 3) because cms.json seeds `team` and the about page needs it; `cms_testimonial` gained `key` (seed natural key) and `source`; `cms_counter` gained `suffix` and `position`; `cms_trust_claim` gained `logo_media_id` and `position`; `cms_video` gained `description` and `created_at`; posts gained `noindex`.
- A09-4: Page slugs are the path without the leading slash, 1 to 3 segments (`about`, `policies/delivery`, `farm-development/site-assessment`); `policies/*` always uses the policy template; first segments owned by module routes are refused (`RESERVED_ROOTS`). WP-14: cms.json page slugs should follow this.
- A09-5: Redirects for unmatched paths are answered by the cms catch-all through seo `resolveMissing`, which can only issue 308/307 (Next `permanentRedirect`/`redirect`), before any Suspense so the status is real. Exact 301s on every path need the proxy to call `redirectFor` (request below).
- A09-6: Dynamic cms routes use `generateStaticParams` with a `__no-page` placeholder when nothing is published (Cache Components requires at least one param) and a try/catch so a build without a database still succeeds; params are awaited and existence checked before any Suspense so 404s are real 404s.
- A09-7: Videos render as poster + link out (YouTube, WhatsApp, file); no iframe or third-party thumbnail on the page because the storefront CSP is self-only (`frame-src`/`img-src` would need YouTube hosts). VideoObject JSON-LD still uses the YouTube thumbnail and nocookie embed URL.
- A09-8: Guides lists cache for hours (not days) so a scheduled guide appears within an hour without an admin save.
- A09-9: robots.txt names AI crawlers (`GPTBot`, `ClaudeBot`, `Claude-SearchBot`, `PerplexityBot`, `Google-Extended`, ...) as the plan requires; these are crawler user-agent strings, not tool mentions.
- A09-10: The product SEO tab shows a search preview, length counters, indexing state and the redirects into the product (with add/delete); the SEO title/description/noindex fields themselves stay on catalog's own product columns (seo cannot write catalog tables). It needs the `entitySeo` binding from catalog.
- A09-11: Media fields in admin forms take a media asset id (text) until a media picker exists; rich text is an HTML textarea sanitised with core `safeHtml` on save and again on read.
- A09-12: `seo` has no settings and no events; robots/llms copy and disallow paths are host config. The 404 log is pruned daily (`seo.prune-not-found`, 30 days and < 5 hits, fixed rows after 90 days) instead of capping inserts.
- A09-13: OG cards use `ogColors` from the host (default neutral white/black) because satori cannot read CSS variables and packages may not hold hex values; Kannada text is not drawn (no Kannada font bundled).
- A09-14: Shipping details (`shippingDetails`) are left out of Offer JSON-LD (optional for Google; needs shipping rates the seo module does not own).
