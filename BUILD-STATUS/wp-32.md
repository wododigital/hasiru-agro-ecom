# WP-32 storefront fixes: seed, links, account redirect, real 404s (status: done)   updated 2026-10-20T10:30+0530

Branch `wp/wp-32` from `ecom-build` 07a4b0c. Own DB `ecomkit_wp32b` (fresh `db:fresh` + 6 migrations + `jobs:install`, snapshot `ecomkit_wp32b_base`). No boot wiring touched (`apps/shop/src/boot*`, `instrumentation.ts`, `worker.ts`).

## Shipped

### 1. Seed
- **Media duplicate-derivative crash** (root cause): `deriveAsset` deleted then inserted derivative rows in a transaction without a lock, so two derives of one asset (seed rerun next to the worker's warm job or sweep) both deleted nothing and the second insert hit the `media_derivative` primary key. It now locks the asset row (`SELECT ... FOR UPDATE`) first (`packages/media/src/server/assets.ts`). Test: three concurrent derives of one asset leave one row set.
- **Seed images served as masters, no derivatives** (Shyam's instruction): `importMasters` uploads with `derive: 'none'` and no longer calls `deriveAsset` for existing rows; `uploadFile` stores `derive: 'none'` images as `ready`, so the worker sweep never derives them later. One sharp encode per image (EXIF stripped). `/media/w/<width>/...` already falls back to the master (verified: 200 `image/webp`). Admin uploads still queue derivatives in the worker. The hook imports 4 files at a time and reports a failing file instead of aborting the run.
- **Why only ~202 of ~588 images loaded**: not missing files. The media hook ran sequentially and spent most of its time encoding the AVIF/WebP ladder (about 13 images a minute under load), so every earlier run was stopped by its time box before finishing. With master-only import a fresh `seed:load` imports all **587** assets (459 old-shop product photos, 64 current-site photos, 64 Wikimedia photos) in under 3 minutes. The backup's other ~19,000 files are WordPress thumbnails, theme assets and duplicates; only images a product or page uses are masters (unchanged rule).
- **Products without photos**: 69 live plants had `image_needed` although WP-13 had sourced real Wikimedia Commons photos for them (`data/media/sourcing-log.json`) that nothing linked. `fill-gaps` now uses the sourced photo when the backup has none (`registerSourcedImage` in `tooling/scripts/seed/lib/media-plan.ts`), with a review note carrying the credit; the media step writes manifest records with licence, author, source URL and `credit_required` (attribution is shown by `creditLine`). Products still without a photo: 3 (HAP-0060 Biriba, HAP-0120 Khanduchi, HAP-0200 Grapes Mango; no allowed-licence Commons photo, see sourcing log). No AI images.
- **10 skipped products** (HAP-0006, 0045, 0092, 0093, 0171, 0174, 0188, 0197, 0225, 0273): old Woo meta descriptions over the catalog's 320-char limit and two short descriptions over 1000. The seed build cuts them at a sentence (`wooSeo`, `wooShort` in `fill-gaps.ts`). All 292 products now load; inventory seeds 294 levels with no unknown SKUs; planting models get 353 members (the 4 SKUs missing before are present).
- **inventory_level**: the verifier's SQL resolver fix holds; every active variant has a level (query: 0 active variants without one).
- **Links**: footer menu and legacy redirects use the real collection slugs (`/plants/timber`, `/plants/fruiting`, `/plants/other`, subcollections `/plants/fruiting/desi` etc.) in `cms-content.ts` and `legacy-redirects.ts`; the admin UI stories page link too. Every href in `cms.json` resolves.
- **Policy pages**: seeded `published` + `noindex` (footer links all five). The three with no SRS text show a one-line holding text with the contact phone and email. The cms seed hook used to force every policy to `draft` whatever the file said; it now keeps the file's status and still forces `noindex` and the policy template.
- **About, contact, why-choose-us, farm-development 404s**: pages exist and are published; the 404s came from building against an unseeded DB. Built against the seeded DB they are 200.
- `seed:load` now calls `apps/<app>/src/boot.ts` `boot({ mediaDir })` when that file exists, so catalog and cms link images to media assets with the app's wiring. In this worktree `boot.ts` does not exist yet (boot agent), so product images are not linked yet; the log says so.

### 2. Account pages
`/account/profile`, `/account/addresses`, `/account/land` (customers) call auth's `requireCustomer(path)`; `/account/reviews` (reviews has no auth dependency) does the same redirect with `getViewer()`, keeping a valid `?product=<uuid>` in `next`. A signed-out visitor gets `NEXT_REDIRECT` to `/account/login?next=%2Faccount%2F...` (the target is a fixed path, and the login action re-checks it with `safeNextPath`). The redirect streams (meta refresh + client redirect), because auth's `AccountLayout` owns the Suspense boundary; no render error.

### 3. Real 404 status
Cause: with `cacheComponents` + `partialPrefetching`, a slug not returned by `generateStaticParams` gets the shared fallback shell (status 200) while the real render runs in the background; `notFound()` then only adds `noindex` (later requests were 404 once cached). Fix: Next 16.4's per-param `unstable_paramMatching: { <param>: 'blocking' }`, so an unlisted slug waits for its full render and `notFound()` sets the status. PPR stays: listed slugs keep their prerendered shells and new products still render on demand. Set through manifest `segmentConfig` on `/plant/[slug]`, `/input/[slug]`, `/plants/[collection]`, `/plants/[collection]/[sub]`, `/[...slug]`, `/policies/[slug]`, `/guides/[slug]`, `/models/[model]`, `/plants/for/[model]`, `/grow-in/[district]`; stubs regenerated with `modules:sync` (shop 10 files, minimal 4).
