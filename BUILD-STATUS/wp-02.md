## Assumptions (numbered A02-n, dated)
- A02-1 (2026-10-20): "`auth generate` schema committed" is met by a hand-written `src/schema.ts` in the generated shape plus a drift test against Better Auth's `getAuthTables(authOptions())` (the Better Auth CLI is not installed and agents may not add dependencies; Better Auth's own runtime schema check, on by default, also validates it).
- A02-2 (2026-10-20): Phone codes are issued and stored by this package (HMAC with a key derived from `INTERNAL_SECRET`, `<hash>:<attempts>` in `auth_verification`), because the phoneNumber plugin stores codes in plaintext. The plugin still verifies (through its `verifyOTP` hook) and creates the user and session. Email codes use the emailOTP plugin with the same keyed hash.
- A02-3 (2026-10-20): Over HTTP `/api/auth/*` exposes only `/get-session`, `/sign-out`, `/ok`; all sign-in flows run as server actions / server functions that carry the rate limits, lockout and generic answers. Better Auth's built-in rate limiter is off (core `rateLimit` is used).
- A02-4 (2026-10-20): `CustomerViewer.customerId` = auth user id (one account, one customer). WP-16 keys `customers_profile` by it.
- A02-5 (2026-10-20): auth emits `customer.created` (payload `{ customerId }`) from Better Auth's user-create hook (not in the sign-up transaction; emit failures are captured). WP-16 should subscribe rather than emit its own for account creation.
- A02-6 (2026-10-20): Phone-only customers get the placeholder email `<digits>@phone.invalid` (Better Auth requires an email); the viewer reports `email: null` for it.
- A02-7 (2026-10-20): Staff 12 h limit is enforced on every request from `session.createdAt` (and the row is created with a 12 h expiry); Better Auth's sliding refresh may extend the stored expiry, which does not matter because the viewer check is authoritative.
- A02-8 (2026-10-20): Lockout counters live in `auth_verification` (`staff-lockout:<email>`), counted per email whether or not it exists. The authenticator step uses Better Auth's own lockout (5 wrong codes, 15 min).
- A02-9 (2026-10-20): Role matrix: `owner` always has every permission (never read from the table). The seed inserts defaults only for roles with no rows, so an owner's edits survive re-seeding.
- A02-10 (2026-10-20): Staff management API (`listStaff`, `setStaffRole`, `setStaffDisabled`, `resendInvite`, `getRoleMatrix`, `setRolePermissions`) is server-only here; WP-08 owns the `/admin/staff` and `/admin/roles` screens. No admin nav items are declared by auth.
- A02-11 (2026-10-20): The authenticator setup screen shows the setup key and an `otpauth://` link, no QR code (no QR dependency in the catalog).
- A02-12 (2026-10-20): `configureAuth` state lives on `globalThis` (`Symbol.for('ecomkit.auth')`) so the instrumentation bundle and route bundles share it. Without the notifications module, development prints codes and invite links to the server log; production throws `NotConfiguredError` (captured) and invite functions still return the link.
- A02-13 (2026-10-20): `requestHeaders()` calls `connection()` before reading headers: viewer resolution reads the clock and must never run in a prerender or runtime prefetch (found in the trial `next dev`).
- A02-14 (2026-10-20): `apps/shop/app/(shop)/account/layout.tsx` imports the generated registry with a relative path and one `eslint-disable-next-line no-restricted-imports` (the boundary pattern `../../*/src/**` also matches this app-internal path).
- A02-15 (2026-10-20): `dependsOn: ['core', 'ui']` (the plan said core only; the pages render `@ecomkit/ui` primitives).
