- `packages/search/src/domain/`
  - `bitset.ts`: Uint32 bitsets with base64 encoding, plus and/or/popcount.
  - `facets.ts`: facet config (`DEFAULT_FACET_CONFIG`, cro-ux 2.1 facet set in buying-intent order) and `facetValuesFromProduct` (rainfall buckets by overlap, bearing buckets, models from `spacing_ft`, tags, stock).

    - OR within a facet, AND across facets.
    - Disjunctive counts, so a facet's own selection does not narrow its own counts.

    - Sorts: recommended, relevance, price both ways, bearing, newest.
    - Request-time extra facets.

    - Pure state transitions.
  - `url-state.ts`: fixed order `q, f, sort, page`, zod-validated parsing that drops junk.

## Assumptions
- A05-1 (2026-10-20): `FacetIndex` (frozen) is extended, not changed. `SearchIndex extends FacetIndex` adds `docs` (slug, kind, name, local name, scientific name, aliases, short keys) so suggest runs over `/facets.json` as the plan says. `SearchSourceRow extends FacetSourceRow` adds those text fields.
- A05-2 (2026-10-20): WP-04 runs in parallel and `facetSource()` does not exist yet. Search therefore reads the catalog tables itself (`src/server/source.ts`), using the plan section 3 column names, and maps them with `facetValuesFromProduct` in search's domain. Price (`catalog_variant` + `pricing_price`) and stock (`inventory_level`, honouring `availability_override`) join only when those tables exist.
- A05-3 (2026-10-20): the trgm index is one expression index over `search_haystack(name, name_kn, scientific_name, search_aliases)` (an immutable SQL function, because `array_to_string` is only stable), not four column indexes. Queries AND one `ILIKE` per token, because `ILIKE ALL (array)` cannot use the index (verified with EXPLAIN).
- A05-4 (2026-10-20): "In stock" defaults ON (plan 5.1 wins over cro-ux "default off"). Clearing it is written as `f=stock:`. "Clear all" clears it too.
- A05-5 (2026-10-20): URL state is one `f` param packing all filters (`key:v1,v2;key2:min-max`), in the plan's fixed order `f, sort, page`, with `q` first on `/search`. Price in the URL is in rupees, and the index stores paise.
- A05-6 (2026-10-20): "Fits my district" is an extra facet computed at request time (`ExtraFacet`), supplied by the host from the places service for the saved district. Search cannot reach `registry.service('places')` from its own route modules. With no district, the facet and its quick chip are hidden. No district picker ships here (places/planting own the location picker).
- A05-7 (2026-10-20): the yield facet is not built: `yield_text` is free text with no buckets. "Bulk deals" and "Rating 4+" quick chips are not built: tier and review data are not in the index. Both are noted in the README facet list.
- A05-8 (2026-10-20): `FacetResults` takes server-rendered cards for the whole listing scope as `Record<id, ReactNode>` and only picks and orders them. The ceiling is in a `ponytail:` comment: switch to a cards endpoint past about 300 products per listing. `/search` uses a text-only `SearchHitCard` until it is wired to the catalog product card.
- A05-9 (2026-10-20): the zero-result filter-combination log goes to `search_query_log` (q empty, `filters.f`) through `POST /api/search/log` (sendBeacon). Search queries are logged from the `/search` page with `after()`. No analytics events are emitted (WP-12 owns `filter_apply`/`search` beacons).
- A05-10 (2026-10-20): the zero-result CTAs come from settings. `assistanceUrl` accepts https only, `guidedHref` must be a store path, and both default to empty (hidden), which keeps the package brand-neutral.
- A05-11 (2026-10-20): UI tests use `react-dom/server` (no DOM library is declared for search). Interaction tests live in `apps/shop/e2e/wp-05.spec.ts` and were run by hand with Playwright against `next start`.
- A05-12 (2026-10-20): Vitest 5 changed benchmarks to a `bench` test-context fixture in `*.bench.ts` files that run only under `vitest bench`. The gated p95 < 80 ms assertion is therefore a normal test in `suggest.test.ts`, and `test/suggest.bench.ts` reports the distribution.
- A05-13 (2026-10-20): the admin nav item "Search insights" sits in the Analytics band (order 640, `analytics.read`). The admin page lives in `src/admin/` (admin copy is English-only); the route file only re-exports it.
