## Assumptions (numbered A25-n, dated 2026-10-20)
- A25-1: The plant calculator suggests the commercial spacing first, then food forest, then miyawaki (line models never fit a grid). The plant list comes from catalog `listProducts` + one cached `getProduct` per plant (card rows carry no spacing); see request R1.
- A25-2: `farmcalc_dosage_rule` deviates from the plan's columns: `amount` / `pack_size` instead of `kg_per_plant` / `pack_kg` (litres exist, and per-acre rules), plus `basis per_plant|per_acre`, `unit kg|L`, `min_packs`, `use_plant_compost`, `is_active`, `position`, timestamps; unique `(input_product_id, basis, role, age_band)`. `input_product_id` is a plain uuid, not a foreign key (pricing does the same; keeps the module droppable).
- A25-3: Green-manure seed (D39 "seed calculation") is a per-acre dosage rule on the seed input (admin-editable), not a separate setting. The module has no settings schema.
- A25-4: Rules are seeded from the dosage data on input products (`inputs.json` `input.dosage_rules`, imported by catalog onto `product.dosageRules`): role null -> `any`, `per_block` skipped (derived), `per_acre` gets `min_packs = 1`, a rule whose note mentions `compost_kg` gets `use_plant_compost`. All seeded rules are active, so the recommended set is 7 inputs, not the plan's 5: Farm Compost (1 kg per plant, or the plant's own at-planting kg) and Neem Oil (1 L per acre) are included. Admins can switch them off.
- A25-5: Seed data says Jeevamrutha 4 L per acre in 5 L cans (1 can per acre); the plan and prototype say 4 cans per acre (`max(1, ceil(acres x 4))`). The engine reproduces the plan formula with a 20 L per acre rule (tested); the seed keeps the data's 4 L. Client question (see requests).
- A25-6: The compost calculator works at the "at planting" age band only (the plan names no age choice); rules for other bands are used by callers that pass `ageBand`.
- A25-7: "Plants in my cart" mode needs the visitor's cart lines through `configureFarmCalculators({ cartLines })`; without the binding (or with no plants in the cart) only "Enter my own" shows. Cart plants get their role from size class (A12) and their own compost kg.
- A25-8: "Add to cart" buttons render only when `configureFarmCalculators({ registry })` says the cart module is on; `cart` is `optional` in the manifest (plan listed it as a hard dependency), so a store without cart can still show calculators.
- A25-9: The cart call is a small local `addToCart` in `src/ui/cart.ts` speaking A04-10 (catalog's `changeCartLine` is not exported from a client-safe entry). Flagged `ponytail:` for the Wave 5 audit (request R3).
- A25-10: planting-3d gets its layout from a host binding `configurePlanting3d({ layout })` instead of importing `@ecomkit/planting` internals (WP-24 is in the same wave and had no API yet). The route 404s until WP-28 binds it.
- A25-11: Patch sizes are per model slug in `DEFAULT_PATCHES` (hyphen and underscore slugs are the same), overridable through `configurePlanting3d({ patches })`. The patch maps each position to the block plant at the same grid index modulo the block's grid (not literal tiling), so spacings that do not divide 36 ft still look even.
- A25-12: Archetypes: explicit hint, else a banana / plantain name, else timber group, else canopy (shrub / climber -> shrub, small tree -> small fruit, large / medium tree -> large fruit when fruit or role M, else timber), else role (M large fruit, X timber, O shrub). The GLB replaces large fruit trees whose name contains "mango".
- A25-13: The GLB ships in the package (`assets/mango.glb`) and is referenced with `new URL(..., import.meta.url)` from the three chunk (bundler emits a hashed static file), not copied into media (media's pipeline is images only).
- A25-14: GLTFLoader's embedded textures load through `TextureLoader` (`<img>`), because the storefront CSP's `connect-src 'self'` blocks fetch of `blob:` URLs while `img-src` allows `blob:`.
- A25-15: Scene colours (sky, grass, soil, bark, leaves) are sRGB triples in `scene.ts`, not hex and not design tokens (scenery, not brand); role rings, labels and the 2D plan read `--color-role-*`, `--color-primary`, `--color-accent` at runtime.
- A25-16: `fill(template, values)` message helper exists in both of my packages (places has `format`, search has `fmt`): no shared helper exists in core or ui yet (request R4).
- A25-17: 3D budget test: Vite build of what the route adds (react/next external) plus a 120 KB framework baseline must stay under 450 KB; the real Next build measured 354 KB total.
