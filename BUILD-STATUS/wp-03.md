## Assumptions (numbered A03-n, dated)
1. A03-1 (2026-10-21) One render path, not two: derivatives are pre-generated by sharp (AVIF q50 + WebP q75, ladder 160/320/480/640/800/960/1280/1920 capped at the master width) and served by `/media/w/<width>/…` with Accept negotiation through a custom next/image loader (`mediaLoader`). Next's on-demand optimizer and `.next/cache/images` are then unused. The plan's "worker warms sizes after upload" is the `media.warm` job generating the derivatives in the worker. Without the loader config (request R1) next/image falls back to its built-in optimizer on the master, so nothing breaks.
2. A03-2 (2026-10-21) One width ladder for every image instead of product 160 to 800 and site 480 to 1920: no preset column is needed and product masters wider than 800 get PDP-zoom sizes. Cost: a few extra AVIF encodes per wide product master at seed time.
3. A03-3 (2026-10-21) Schema additions to the plan's `media_asset`: `is_private bool` (private files need a flag; storage key also starts `private/`), `updated_at`, and source enum value `client` (data/seed/SCHEMA.md uses it for the owner's field photos). `media_usage.asset_id` is `ON DELETE RESTRICT`; `media_derivative` cascades.
4. A03-4 (2026-10-21) Masters are WebP q90 fitted inside 2560 px. Upload cap 12 MB (matches nginx), decode cap 50 MP. Animated GIFs keep the first frame. HEIC is refused with its own message (the prebuilt sharp has no HEIC decoder); iOS Safari usually converts to JPEG on upload.
5. A03-5 (2026-10-21) Video uploads are not accepted (enum value kept for later); CMS videos are links. PDFs are the only documents and are always private (signed URL, 10 minute default, `Content-Disposition: attachment`, `CSP: sandbox`, `no-store`). Images may be private too (`isPrivate`, e.g. land photos on enquiries): no derivatives, no blur, no public URL.
6. A03-6 (2026-10-21) Dedupe returns the existing asset whatever its privacy flag; `getImage` never returns a private asset, so a public use of bytes first uploaded privately renders the placeholder until re-uploaded with different bytes.
7. A03-7 (2026-10-21) Storage root is deploy config, not a module setting: env `MEDIA_ROOT` (default `<cwd>/storage/media`). No media settings page.
8. A03-8 (2026-10-21) Library permission: view and edit both require `media.write` (there is no `media.read` in the frozen catalogue). Upload route is staff-only; storefront modules call `uploadImage()` from their own handlers with their own rate limits.
9. A03-9 (2026-10-21) A `share.jpg` (largest derived width, q80, white background) is generated per public image for consumers that need JPEG (WhatsApp template headers, Meta catalog, email); `shareSrc(storageKey)` gives its URL.
10. A03-10 (2026-10-21) The seed hook derives default alt text from the file name ("products/alphonso-mango-2.webp" -> "Alphonso mango") on insert only; an edited alt is never overwritten. Metadata changes in the manifest update the row; unchanged records change zero rows.
11. A03-11 (2026-10-21) Admin pages call `connection()` before the permission check so the cacheComponents build never prerenders them (the trial build failed with ForbiddenError until this was added).
12. A03-12 (2026-10-21) The `ui` and `mocks` export entries of the package scaffold stay unused (no storefront component or mock route needed); credit text is data on `ImageRef.credit` for the rendering module to show.
