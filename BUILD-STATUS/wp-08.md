## Assumptions (numbered A08-n, 2026-10-20)
- A08-1: admin-shell pages are thin hand-written host files, not manifest `admin.pages` stubs: a generated stub re-exports a package default and cannot hand it the app registry, and module-level registry binding is unreliable for server actions on a cold process. The README lists the seven host files; `modules:sync` keeps hand-written files.
- A08-2: the layout's 404 needs the request path to let `/admin/login` (WP-02, inside this layout) through. It reads `x-pathname`; until the proxy sets it, the layout renders non-staff requests bare and every admin page guards itself with `requireAdmin()` (404 for non-staff). Pages of other modules must guard themselves too (plan section 6 already requires it).
- A08-3: with cache components the gate runs inside a Suspense boundary, so a non-staff `/admin` request gets the not-found page (noindex) with HTTP 200, not 404. A true 404 status needs a proxy-level optimistic check (request below).
- A08-4: `adminSearch[]` and `settingsUrls[]` are extra manifest keys read structurally and validated with zod until the core contract adds them (request below).
- A08-5: `settings.secrets` and `staff.manage` are owner-only; the roles screen never grants them (UI disabled and the zod schema refuses them), matching the CONVENTIONS role matrix.
- A08-6: the staff screens talk to auth through a `StaffAdmin` port whose method names match WP-02's `@ecomkit/auth/server` exports (checked against WP-02's worktree); mutators return `Promise<unknown>` so return shapes may change.
- A08-7: settings form semantics: an untouched or empty secret keeps the stored value (no "clear secret" button yet; core `setSettings(null)` supports it); empty plain text stores ''; an empty optional email/url/select or number keeps the stored value; object/union fields are read-only (edited by the module's custom panel).
- A08-8: settings page title is the module's own nav label for `/admin/settings/<id>` if it declares one, else the id in words; no contract change.
- A08-9: "last status" of a settings action is the latest `settings.action` audit row; action `detail` is not shown or stored.
- A08-10: audit viewer pages by `created_at` keyset (core `listAudit`); actor shown as type + short id (no name lookup, which would need staff.manage).
- A08-11: the dashboard reads the clock after a request-time marker (`connection()`), and the default range is the last 30 days ending today in IST. An IST date helper lives in admin-shell domain (`istDate`); core has none.
- A08-12: admin copy is English literals in `src/admin` (admin exempt from the messages rule); no `messages.ts` for this package.
- A08-13: the mobile nav drawer is portalled to `body`, so it carries `data-surface="admin"` itself to keep the admin palette.
