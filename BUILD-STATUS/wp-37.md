# WP-37 CSP that lets private pages hydrate (status: done)   updated 2026-10-21

Release blocker from the final gate. Worktree `.worktrees/wp-37`, branch `wp/wp-37` (from `ecom-build` c14131c), committed, not merged, not pushed. DB `ecomkit_wp37`, port 3371. No dependency added, no contract change.

## Cause
`apps/shop/proxy.ts` sends `script-src 'self' 'nonce-X' 'strict-dynamic'` on `/admin /account /checkout /pay`. Next stamps the nonce only on scripts it renders for the request. With `cacheComponents` these routes were partial prerenders (`◐`): the static shell, including the chunk `<script>` tags and the inline bootstrap, was written at build time without a nonce, and `'strict-dynamic'` makes the browser ignore `'self'`. Measured on the baseline production build in Chromium: checkout 7 of 25 scripts nonced and 33 blocked, admin login 8 of 24 and 45 blocked, admin orders 9 of 25 and 44 blocked; none of them hydrated (no autosave, no live quote, no OTP sign-in, no admin islands). Smoke never runs JS, so it stayed green.

A second, smaller violation showed up on every storefront page: Zod 4 probes `new Function("")` once to pick its JIT parser. With no `'unsafe-eval'` the browser reports that swallowed probe as a `script-src` violation (harmless, but noise that hides real ones).

## Choice: (a) make the nonce work
Every segment under a nonce prefix now renders fully per request, so there is no static shell to miss the nonce:
- `app/(admin)/layout.tsx`, `app/(shop)/account/layout.tsx`, new `app/(shop)/checkout/layout.tsx`, new `app/(shop)/pay/layout.tsx`: `await connection()` before rendering, plus `export const instant = false` (Next 16.4's opt-out of the "non-empty static shell" validation for these routes only).
- Build output: admin `◐ 73 / ƒ 1` -> `◐ 17 / ƒ 57`, account `◐ 8` -> `ƒ 8 (+1 ◐)`, checkout `◐ 2` -> `ƒ 1 (+1 ◐)`, pay `◐ 1` -> `ƒ 1`. The `◐` entries left are the `└` fallback lines of `[param]` routes; at runtime `/admin/orders/<id>` serves 25 of 25 scripts nonced, so they render per request too. Storefront unchanged: 47 `◐` before and after.
- Next still sends `x-nextjs-prerender: 1` / `x-nextjs-postponed: 1` on these responses (it does on every cacheComponents route); the proof is the HTML: every `<script>` carries the request nonce.
- Why (a) over (b): it keeps the strongest policy (nonce + `strict-dynamic`, no `'unsafe-inline'` for scripts) on exactly the pages that handle payments, OTP and staff sessions. The cost is only the static shell of private, uncacheable pages; storefront PPR is untouched.

Also:
- `apps/shop/instrumentation-client.ts`: `z.config({ jitless: true })` in the browser (Zod 4.6.5 skips the probe under `jitless`; client parsing is small).
- Marketing vendors wired: `proxy.ts` merges `cspSources()` from `@ecomkit/marketing/server` (only when `marketing` is in `modules.config.ts`; memoised 60 s inside marketing, so no query per request; a failed read answers no vendors) into `script-src`, `connect-src`, `img-src` and `frame-src` (`frame-src` only when a vendor needs one). `CSP_VENDOR_SOURCES` stays as an extra allowlist for script and connect. Vendors now also reach checkout/account/pay (the tag loader runs in the shop shell there; before, their beacons were blocked by `connect-src 'self'`). Admin loads no tags and gets no vendor hosts. `proxy` became `async`.
- Every other directive is unchanged on both policies: `default-src 'self'`, `style-src 'self' 'unsafe-inline'`, `font-src 'self'`, `frame-ancestors 'none'`, `object-src 'none'`, `base-uri 'self'`, `form-action 'self' https://*.phonepe.com`, plus nosniff, referrer policy, permissions policy, `X-Frame-Options: DENY`, HSTS.

## Open / notes
- React #418 on the storefront (above): owner is the storefront shell; likely a value that differs between the prerendered shell and the client (date or locale formatting).
- The admin global search box never renders: no enabled module registers an admin search provider (`hasSearch` false), so Ctrl+K has nothing to focus. csp-check falls back to a sidebar link (client-side navigation) as the admin island.
- The proxy bundle gets its own small pg pool for `cspSources()` (one read a minute, at most 2 connections in practice).
- A new private prefix needs both the `NONCE_PREFIXES` entry and a layout that awaits `connection()` (docs/CONVENTIONS.md section 12); `tooling/csp-check.mjs` catches a miss in a real browser.
- csp-check is slow on this laptop under swarm load: the whole process was seen stalling for ~10 minutes and then carrying on; its hang guard is 20 minutes per page for that reason.
