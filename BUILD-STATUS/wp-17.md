## Assumptions (numbered A17-n, dated)
- A17-1 (2026-10-20): No FK from `cart_line.variant_id` to `catalog_variant` or from `cart_cart.customer_id` to `auth_user` (plan said `variant_id fk`): same rule as inventory/pricing (modules can be dropped independently). A line whose variant disappears renders as unavailable and leaves the totals.
- A17-2 (2026-10-20): Catalog facts per variant (product id, kind, names, href, weight, image, purchasable, collection/tag ids) come through `configureCart({ variants })`: catalog exports no variant lookup and modules never read another module's tables. Unbound, a cart with lines throws "cart is not configured".
- A17-3 (2026-10-20): Discounts reach the cart through a port in `configureCart({ discounts: { promos, applyCoupon, evaluateCoupon } })` (discounts is optional and has no ServiceMap key). A stored code is re-checked on every view with `evaluateCoupon` so the typing rate limit (10 per 15 min, subject `cart:<id>`) is not spent by page views. Discount eligibility gets `customer: null` in the preview (first-order and segment rules are settled by checkout's quote).
- A17-4 (2026-10-20): Merge on sign-in happens lazily on the first cart read with a customer viewer (no auth hook exists): guest lines merge into the customer's live cart (product lines sum, capped at 100,000; a package in the guest cart replaces the customer's; the customer's coupon wins), the guest cart closes as `merged`. With no customer cart the guest cart is claimed. After sign-out the cookie opens nothing (a guest never sees a customer cart).
- A17-5 (2026-10-20): `cart.updated` is emitted at most once per minute per cart (plus on create, merge and re-open of an abandoned cart); payload is the id, subscribers read fresh state.
- A17-6 (2026-10-20): Abandonment: a cart with lines and no activity for `abandonAfterMinutes` (setting, default 60) becomes `abandoned` with one `cart.abandoned` per idle stretch; any activity re-opens it (`active`). Job `cart.mark-abandoned` runs every 5 minutes. `checkoutSessionId` is null (cart cannot read checkout tables); `hasContact` = signed-in customer or `noteContact` called by checkout.
- A17-7 (2026-10-20): The emitted `cart.abandoned` payload carries an extra `hasContact: boolean` (typed `CartAbandonedPayload`, assignable to the frozen contract type). The contract addition is requested below.
- A17-8 (2026-10-20): Restore links are `/api/cart/restore?t=<cartId>.<exp>.<hmac>` (`signInternal`, purpose `cart-restore`, `restoreLinkDays` default 30). Opening one on a device gives that guest cart a fresh cookie token (the old device's cookie stops working) and merges whatever guest cart the device had. A customer's cart needs that customer signed in (redirect to `/account/login?next=/cart`). Flows' `/r/[token]` (WP-22) can redirect to `restorePath(token)`.
- A17-9 (2026-10-20): Cart preview totals use `interState: false` and no GST rate on charges (shipping quotes do not carry one); totals are unchanged by either, only the tax split. Checkout's quote sets both from the address.
- A17-10 (2026-10-20): Delivery quotes in the cart use the visitor's `district` cookie (same as catalog) as the address and pass `packingFeePaise: 0` per line (shipping computes its own packing rules into `packingPaise`). Only an available method is ever selected; nothing is preselected.
- A17-11 (2026-10-20): "Recommended inputs" is a cart section (plants present, no inputs) with a link to the `inputsHref` setting (`/inputs`); concrete recommendations are left to farm-calculators via a `cartBlocks` entry (the engine is WP-25's).
- A17-12 (2026-10-20): New-cart rate limit: 30 per hashed `X-Real-IP` per hour (`cart-create:<hash>`); without a proxy-supplied IP (local dev, Playwright against `next start`) creation is not limited. Existing carts are never limited; lines per cart are capped at 200 and qty at 100,000.
- A17-13 (2026-10-20): The no-JS form post answers errors with 303 `/cart?error=<code>`; the page shows the matching `messages.notices` text. Restore failures use `restore_<reason>`.
- A17-14 (2026-10-20): Server actions `refresh()` the route after each change, so server-rendered parts (summary, cart blocks such as the truck meter) re-render; client islands only hold the optimistic quantity. Islands receive only strings (no message functions cross the server/client boundary).
- A17-15 (2026-10-20): The browser event `cart:changed` is defined again in `packages/cart/src/ui/events.ts` (same string as catalog's `CART_CHANGED_EVENT`): importing catalog's ui index into a client island would pull its server components.
- A17-16 (2026-10-20): `dependsOn: ['core', 'ui', 'catalog', 'pricing']` (plan: core, catalog, pricing; the pages render `@ecomkit/ui` primitives, as auth A02-15). `@ecomkit/catalog` stays declared in package.json without an import (the hard dependency is the bound variants port).
- A17-17 (2026-10-20): The generated route stubs (`app/(shop)/cart/page.tsx`, `app/api/cart/{,lines/,restore/}route.ts`) are not committed: they come from the manifest via `modules:sync` (orchestrator), as A06-14.
