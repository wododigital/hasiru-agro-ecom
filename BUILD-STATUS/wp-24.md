## Assumptions (A24-n, 2026-10-20)
- A24-1: No `planting_pattern` / `planting_plan_line` tables (plan section 2.5 lists them, section 3 does not): the pattern is a jsonb column on the model (`{kind: 'rows', rows}` | `{kind: 'random', mix, seed}` | `{kind: 'line', rows: [one]}`) and the plan stores its lines per model in `selections` jsonb `{ [modelSlug]: { lines: [{productId, role, qty}], blocks, totalPlants, emptyRoles } }`.
- A24-2: The plan stores `district_slug` (+ a label snapshot), not `district_id`: the places contract `DistrictRef` has no id. Land profiles are saved with `districtId` null and the purpose slug.
- A24-3: Model slugs follow `data/seed/models.json` (`commercial`, `food-forest`, `miyawaki`, `boundary`), not the underscore spelling in plan section 3; per-plant spacing comes from `products.json` `plant.models.<slug with underscores>.spacing_ft`.
- A24-4: Manifest `dependsOn` is `core, ui, catalog, pricing, customers, places`; `cart`, `farm-calculators` and `auth` are `optional` (plan listed them as hard): cart and farm-calculators are Wave 2 siblings with no exports yet, auth must not be imported directly (auth README), and all three are reached through `configurePlanting` ports that degrade (no package button, no inputs block, OTP mode answers `not_configured`).
- A24-5: An unlocked plan is visible to anyone holding its link (the WhatsApp share must open for the recipient; the page has no personal data). The `plan_visitor` cookie ties plans to a visitor for follow-up, it does not gate viewing. Locked plans never send quantities, prices or inputs to the browser.
- A24-6: Picks per role: fitting members (fit good or ok; no climate data = ok), default picks first, then good before ok, then admin position; `picks_per_role` setting (default 3). Seeded models mark the first 3 members per role (client sort order) as default picks. A role with no fitting member is left empty and the page says so (not back-filled with unsuitable plants).
- A24-7: Miyawaki uses exact role counts from the mix (largest remainder: 32 / 162 / 130 per 324-cell block) placed by a seeded shuffle (seed = plan id; the model seed on model pages), so counts and drawing agree.
- A24-8: The seed hook only creates models that do not exist yet (with their members); existing models belong to the admin, so re-seeding never undoes staff edits and a second run changes nothing.
- A24-9: OTP unlock uses the auth module's `otp.login` code (via the port), not a separate `otp.unlock` template; verify signs the customer in, as A23 requires.
- A24-10: "Details" expands the facts inline (bearing, yield) with a link to the PDP instead of opening the PDP in a sheet; "View more varieties" reveals the role's alternates with qty 0.
- A24-11: Client-side line prices use the quote's current or next tier (`unitAt`); the cart reprices against the full ladder when the package is added.
- A24-12: Without JavaScript the wizard does not work (district typeahead is the island, per plan "static shell, client island"); the unlock form and both API routes do accept plain form posts (soft mode end to end).
- A24-13: Admin lives in the Products band (`order 250`, permission `products.write`). Generate also sets the `district` cookie the catalog reads for fit chips.
- A24-14: "Build it for me" links to `build_for_me_path` with `?source=plan&plan=<id>&district=<name>&acres=<n>`; prefilling the enquiry form from these is the enquiries side.
