## Assumptions (A26-n, 2026-10-20)
- A26-1: The model call is non-streaming (`messages.parse` with `output_config.format`); the route streams the **validated** text. A grounding validator needs the whole reply, so streaming raw model tokens would show unvalidated prices. Perceived speed comes from the `meta` event (products known as soon as the rules engine finishes) and the drawer's pending state.
- A26-2: The narrator never sees product ids: products are `p1..p6` refs with every number pre-formatted (`Rs 450 each`, `Rs 355 each from 50`); refs are mapped back to ids after validation.
- A26-3: Validator rule: a sentence is removed whole when it quotes a rupee amount not present in the facts (or typed by the visitor) or a count of items ("40 saplings", count words from messages) not present in the facts; unknown refs are removed and reported. Correct numbers attributed to the wrong product are not detectable and are accepted.
- A26-4: Provider modes `template | mock | live` (default `mock`). Mock goes through the real SDK to `/api/_mock/claude` at `INTERNAL_BASE_URL`; with `ENABLE_MOCKS` off (production) mock falls back to the template, so production with the default setting answers rules-only until an admin picks `live` and saves a key.
- A26-5: No server-side refusal `fallbacks` parameter: Haiku 5.5 (the default, A20) has none, and the plan's fallback on refusal is the template answer, not a second model. Same for Sonnet 5.5 when selected.
- A26-6: The live client's `fetch` is core `safeFetch` pinned to `api.anthropic.com` (45 s timeout, SDK `maxRetries: 1`); every call goes through `integrationCall` (provider name `assistant-model`) so monitoring sees failures.
- A26-7: History = the last 8 transcript messages of the conversation from the database (product tokens replaced by names), never sent by the client. An unknown conversation id starts a new conversation.
- A26-8: Rate limits: `assistant-ip:<salted IP hash>` per day (100) checked before anything is written, and `assistant:<conversationId>` per hour (20). The first question of a new conversation is counted right after the conversation is created. Without `INTERNAL_SECRET` (local dev) all visitors share the `local` bucket.
- A26-9: Narration cache key = sha256(prompt version, provider, model, effort, store context, history, facts text), so only exact repeats hit; rows older than 30 days are pruned nightly with transcripts past `transcriptDays` (default 90).
- A26-10: Columns added to the plan's tables: `ai_conversation.last_at`, `ai_message.source` (`model|cache|template`); `visitor_id` holds the salted IP hash. No foreign keys to other modules.
- A26-11: Companions default to the catalog's admin-curated `catalog_related` rows with relation `companion`; planting's model-role companions plug in through `configureAssistant({ companions })` (there is no `ServiceMap` key for it and contracts are frozen).
- A26-12: District fit is computed only when the question asks about fit/place or the drawer is in Plan mode; a place named in the question wins over the `district` cookie; `not_recommended` products are dropped from fit answers.
- A26-13: One product card: the rail under an answer is the catalog `ProductCard`, rendered by a server action returning RSC. Inline `[[id]]` tokens render as the product name link plus a small "+" chip that speaks catalog's cart contract (`POST /api/cart/lines` JSON, `cart:changed` event), passed from the server wrapper only when `registry.has('cart')`.
- A26-14: Default copy is brand-neutral (delivery and returns notes point to the policy page / pincode check). Hasiru wording ("Ask our plant expert", the no-return policy, nursery delivery zones) goes in `apps/shop/messages/en.ts` through `configureAssistant({ messages })`.
- A26-15: Cost guardrail is a monthly token cap (plan section 10 "monthly token cap") computed from `ai_message`, not a daily request cap; over the cap every answer is the template. Answers with no products and one canned note never call the model (`note_only`).
- A26-16: Transcripts need `customers.read` (they can hold personal details typed by visitors); nav "Assistant transcripts" in the Customers band at 340. Settings live at `/admin/settings/ai-assistant` (admin-shell renderer) with one `test-connection` action.
- A26-17: Area quantities use the first spacing found in the product's `spacing_ft` (rectangular grid `acres x 43,560 / (L x W)`), labelled with that spacing; the planting wizard remains the place for model-specific plans.
- A26-18: The plan's "assistant 20/session/h" maps to per conversation; the research's "100/day per IP" is the second limit.
- A26-19: The mock route path keeps the vendor name (`/api/_mock/claude/...`, as in the plan); CONVENTIONS section 13 allows vendor names in the provider adapter, its settings and mock only. The system prompt and storefront copy never name a vendor.
- A26-20: The system prompt is about 600 tokens; if it is under the model's minimum cacheable prefix, `cache_read_input_tokens` stays 0 (recorded per answer as `facts.cacheReadTokens`). Hosts adding `storeContext` lengthen the cached prefix.
